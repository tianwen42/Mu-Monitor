## 一、10.15 最终要交付什么

最终只展示一条主链路：

```text
独立设备模拟器
-> TCP
-> 自定义二进制协议
-> 粘包/拆包与 CRC 校验
-> 连接状态机和自动重连
-> 有界数据管道
-> 告警状态机
-> SQLite 异步写入
-> Qt 实时界面
-> Excel 历史导出
```

截止日必须完成：

- [ ] `DeviceSimulator.exe` 可以独立启动，模拟多台设备。
- [ ] `Mu-Monitor.exe` 通过 TCP 连接模拟器并持续接收数据。
- [ ] 使用自定义二进制帧，包含帧头、版本、长度、序号、设备 ID、时间戳、负载和 CRC16。
- [ ] 正确处理 TCP 粘包、拆包和坏帧。
- [ ] 实现连接、断开、重连和心跳超时。
- [ ] 使用指数退避和随机抖动进行自动重连。
- [ ] 高频网络解析不阻塞 Qt UI。
- [ ] 遥测数据通过有界队列进入持久化和 UI 更新流程。
- [ ] 实现高温、高压和离线告警。
- [ ] 告警支持触发、确认和恢复。
- [ ] SQLite 使用后台批次写入。
- [ ] 实时页面展示连接状态、设备状态、数据速率、坏帧数和队列深度。
- [ ] 保留历史查询和 Excel 导出。
- [ ] 至少有协议、CRC、状态机和告警状态机自动测试。

## 六、项目最终要体现的技术点

完成后可以围绕下面六点总结项目，所有数字都必须来自最终测试：

- [ ] Qt6/C++17 开发 Windows 工业设备监控客户端。
- [ ] 设计自定义二进制 TCP 协议，处理粘包、拆包、CRC16 和坏帧隔离。
- [ ] 实现连接状态机、心跳超时、指数退避和自动重连。
- [ ] 设计有界数据管道，将网络解析、业务处理、UI 刷新和 SQLite 写入解耦。
- [ ] 实现告警触发、确认和恢复状态机，并持久化告警事件。
- [ ] 使用 QtTest 对协议、状态机和告警逻辑进行自动化测试。

### 项目总结模板

> 基于 Qt6/C++17 开发工业设备监控客户端，设计自定义 TCP 二进制协议并实现 CRC16 校验、粘包/拆包处理与坏帧隔离；实现连接状态机、心跳检测、指数退避重连和有界数据管道，避免 UI 线程阻塞；使用后台批量写入 SQLite，实现遥测历史存储和 Excel 导出；设计告警状态机，支持告警触发、确认、恢复和事件持久化；通过 QtTest 覆盖协议解析、连接状态和告警逻辑。

面试时不要只说“用了 Qt”，要能解释：

- 为什么要定义长度字段。
- 粘包和拆包分别怎么处理。
- CRC 校验失败后为什么不能继续解析后续帧。
- 为什么队列必须有上限。
- 为什么 SQLite 连接不能随便跨线程使用。
- 告警为什么要使用状态机而不是只插入一条日志。

## 七、风险和降级方案

### 如果 TCP 联调卡住超过两天

先使用本地回环地址和固定测试向量，禁止同时调网络、协议、UI 和数据库。按照“协议测试 -> 本地 Socket -> 模拟器 -> GUI”的顺序逐层排查。

### 如果时间只剩三天

保留以下最小 Demo：

- 模拟器。
- TCP 客户端。
- FrameCodec 和 CRC。
- 自动重连。
- 实时界面。
- 简单阈值告警。
- SQLite 写入。
- 一个协议测试和一个重连测试。

砍掉告警确认、历史分页、设置保存和安装包。

### 如果国庆期间没有开发时间

整体计划至少提前砍掉 P1；同时把测试规模从 10 台设备降到 3 台。不要为了在 10.15 勉强演示而删除协议、重连和后台写库，这三项是项目能否形成可信项目的关键。
